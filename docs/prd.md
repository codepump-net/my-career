# PRD — 개인 포트폴리오 사이트 (cv-portfolio)

| 항목 | 값 |
| --- | --- |
| 문서 버전 | 0.5 (버전별 페이지, 지원 허브, 작성 안내 방식) |
| 최종 갱신 | 2026-08-24 |
| 저장소 | `https://github.com/codepump-net/cv-portfolio` |
| 배포 주소 | `https://codepump-net.github.io/cv-portfolio/` |
| 상태 | `/cv` 작성 완료 / `/coverletter`, `/portfolio` 내용 대기 |

---

## 1. 목적

이력서 · 자기소개서 · 포트폴리오를 **웹에서 바로 열람할 수 있는 형태**로 만들고,
같은 화면을 **PDF 로 추출해 제출용 문서로도 쓰는 것**이 이 사이트의 목적이다.

한 벌의 원본(HTML)에서 두 가지 산출물이 나온다.

- **열람용** — 링크 하나로 공유한다.
- **제출용** — 같은 내용을 PDF 로 내려받는다.

문서를 갱신할 때 웹과 PDF를 따로 관리하지 않는다는 점이 이 구조의 핵심이다.

### 왜 이 방식인가

기존 `nnn-games-website` 프로젝트(회사 소개 `/company`, 게임 기획 `/jumpstart`)에서 이미
검증된 슬라이드 덱 구조를 개인 문서에 적용한다. 발표·공유·PDF 배포가 한 소스에서 해결되는
것을 확인했으므로, 개인 포트폴리오에도 같은 원리를 쓴다.

다만 문서마다 맞는 지면이 다르다는 점을 반영해 **두 체계로 나눴다**(3절).

## 2. 대상과 사용 시나리오

| 대상 | 시나리오 |
| --- | --- |
| 채용 담당자 · 리크루터 | 링크를 받아 브라우저에서 바로 훑는다. 모바일 열람 비중이 높다 |
| 협업·외주 문의자 | 포트폴리오 케이스를 보고 연락처로 이어진다 |
| 본인 | 지원처에 제출할 PDF 를 뽑는다. 발표 자리에서 포트폴리오를 전체화면으로 띄운다 |

## 3. 두 가지 지면 체계

문서 성격에 따라 지면을 나눈다. 두 체계는 서로 독립적이며 공용 코드를 공유하지 않는다.

| | **A4 세로 문서** | **16:9 슬라이드 덱** |
| --- | --- | --- |
| 쓰는 곳 | `/cv`, `/coverletter` | `/portfolio` |
| 지면 | A4 세로 210×297mm | 1280×720px |
| 페이지 분할 | 내용 길이에 따라 브라우저가 결정 | 슬라이드 1장 = 1페이지 (작성자가 결정) |
| 화면 | 회색 배경 위 흰 종이, 세로 스크롤 | 고정 캔버스, 좌우 넘김 |
| 치수 단위 | `px` (종이에 찍히는 크기 고정) | `rem` (화면 크기에 따라 배율 변동) |
| 공용 코드 | `paper/shared/` | `slides/shared/` |
| 안내 문서 | [`paper/README.md`](../paper/README.md) | [`slides/README.md`](../slides/README.md) |

### 왜 나눴나

이력서와 자기소개서는 결국 **A4 로 제출되는 문서**이고 분량이 유동적이다. 고정 높이 슬라이드에
담으면 글이 늘어날 때마다 잘리거나 직접 장을 나눠야 한다. 흐름형 문서로 두면 내용이 늘어도
브라우저가 알아서 페이지를 나눈다.

포트폴리오는 반대다. 이미지와 지표를 가로로 펼쳐야 하고 발표 자리에서 띄울 일이 있으므로
16:9 슬라이드가 맞는다.

## 4. 범위

### 포함

- 포트폴리오 메인 페이지 (`/`)
- A4 세로 문서 2종: 이력서 `/cv`, 자기소개서 `/coverletter`
- 16:9 슬라이드 덱 1종: 포트폴리오 `/portfolio`
- PDF 추출 기능 (세 페이지 모두)
- 한국어 / 영어 2개 국어
- GitHub Pages 배포

### 제외

- 서버, 데이터베이스, 로그인, 문의 폼 등 백엔드가 필요한 기능
- CMS · 관리 화면 (내용은 소스를 직접 고쳐 갱신한다)
- 블로그, 방문자 분석
- 일본어 (필요해지면 사전에 `ja` 를 추가하는 방식으로 확장 가능하다)

## 5. 정보 구조

```text
/                        메인 — 지원 버전 목록, 소개, 연락처
/cv/                     이력서 버전 목록 (링크만)
/cv/default/             이력서      · 기본판
/cv/<버전>/               이력서      · 지원 분야별 맞춤 버전
/coverletter/            자기소개서 버전 목록
/coverletter/<버전>/      자기소개서  · 지원처별 맞춤 버전
/portfolio/              포트폴리오 버전 목록
/portfolio/<버전>/        포트폴리오  · 16:9 슬라이드
```

각 문서의 구성

| 문서 | 절 / 슬라이드 | 내용 |
| --- | --- | --- |
| `/cv` | 머리(이름·연락처) · 01 요약 · 02 경력 · 03 학력 · 04 강의 · 05 논문 · 06 수상 | **작성 완료** |
| `/coverletter` | 머리(지원 직무) · 01 지원 동기 · 02 강점과 문제 해결 · 03 협업과 성장 · 04 입사 후 계획 · 맺음말 | 절 구성 확정, 문장 대기 |
| `/portfolio` | 표지 · 개요 · 케이스 01~03 · 작업 방식 · 연락처 · (부록) 상세 자료 | 대기 |

`/cv` 는 `cv/data/오현석_CV.pdf` 를 원본으로 작성했다. 절 구성은 원본의
OBJECTIVE / EXPERIENCE / EDUCATION / LECTURE / PUBLICATION / AWARDS 를 그대로 따른다.
KO 기준 3페이지, EN 기준 4페이지로 출력된다.

`/coverletter` 는 절 구성이 확정됐고 각 자리에 **작성 안내**만 들어 있다. 문장은 본인이 쓴다.
`/portfolio` 는 레이아웃 확정용 임시 문구(`CONTENT PENDING`)가 들어 있다.

현재 지원 버전은 세 건이다 — 기본판, OVERDARE(Technical Product Manager), 연구·교육(본보기).

## 6. 사용 기술

**빌드 도구를 쓰지 않는다.** 저장소에 있는 파일이 그대로 배포되는 파일이다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 마크업 | HTML5 (정적) | 프레임워크 없이 충분한 규모다 |
| 스타일 | CSS3 수기 작성, 커스텀 프로퍼티로 토큰 관리 | 빌드 단계가 없어 push 즉시 배포된다 |
| 스크립트 | Vanilla JS (ES6), 모듈 번들 없음 | 의존성 0 |
| 폰트 | Google Fonts — Inter, Noto Sans KR | 한글·영문 혼용 본문에 적합하다 |
| 아이콘 | 인라인 SVG | 아이콘 폰트/라이브러리 의존을 만들지 않는다 |
| 점검 도구 | Node.js 18+ (`tools/check.js`) | 배포물의 의존성이 아니라 개발용 도구다 |

### 빌드 도구를 쓰지 않기로 한 이유

참고 프로젝트(`nnn-games-website`)는 Tailwind CLI 로 CSS 를 빌드하지만, 이 사이트는
페이지 4개 규모이고 지면 체계 두 벌 모두 수기 CSS 다. 빌드를 넣으면 배포 경로에 `npm ci` 와
GitHub Actions 설정이 얹히고, 빌드 산출물과 소스의 동기화를 계속 신경 써야 한다. 얻는 것에
비해 유지 비용이 크다고 판단했다.

## 7. A4 세로 문서 (`/cv`, `/coverletter`)

### 지면

A4 210×297mm, 여백 상하 18mm · 좌우 16mm. 96dpi 기준 794×1123px 이며, 문서 내부 치수는
`px` 로 쓴다. 화면과 인쇄가 같은 크기로 맞는다.

### 페이지 분할이 두 벌인 이유

| | 누가 나누나 | 목적 |
| --- | --- | --- |
| 화면 | `paper.js` 가 블록 높이를 재서 시트로 나눈다 | 워드처럼 보이게 하는 미리보기 |
| 인쇄 | 브라우저가 `@page` 여백에 맞춰 직접 나눈다 | **실제 결과. 이쪽이 기준이다** |

둘은 같은 여백·같은 글자 크기·같은 분할 회피 규칙(`break-inside: avoid`)을 쓰므로 장수가
일치한다. 어긋나면 PDF 를 믿는다.

화면 폭이 900px 미만이면 종이 흉내를 포기하고 한 줄기로 흘린다(모바일).

### 버전 관리

지원 분야마다 이력서를 다시 쓰되 **경력 사실은 한 벌만 둔다.** `data.js` 가 사실의 정본이고,
`versions/<이름>.js` 는 "어떤 절을, 어떤 순서로, 어떤 항목만" 보일지를 정한다. 회사명이나
성과 한 줄을 고치면 모든 버전에 함께 반영된다.

**버전 하나가 폴더 하나다** — `<문서>/<버전>/{index.html, version.js}`.
`<문서>/index.html` 은 버전 목록만 보여 주고, 실제 내용은 각 버전 폴더에 있다.

| | 주소 | 검색 노출 |
| --- | --- | --- |
| 버전 목록 | `/cv/` | 허용 |
| 기본판 | `/cv/default/` | 허용 |
| 맞춤 버전 | `/cv/overdare/` | `noindex` 자동 부착 |

쿼리 문자열(`?v=`)은 쓰지 않는다. 지원처에 전달하는 주소가 그대로 읽히는 경로여야 하고,
페이지마다 고유한 파일이 있어야 링크·북마크·검색 정책을 개별로 다룰 수 있다.

**모든 버전은 메인 페이지의 지원 목록에 공개된다**(2026-08-24 결정). 지원처끼리 서로의
문서를 볼 수 있다. `noindex` 는 검색 결과 노출만 막는다. 특정 지원을 감추려면
`applications.js` 에서 항목을 빼고 링크만 직접 전달한다 — 주소를 아는 사람은 여전히 열린다.

### 지원 = 세 문서의 조합

`applications.js` 의 항목 하나가 지원 한 건이며, 이력서·자기소개서·포트폴리오 버전을 묶는다.
메인 페이지는 이 목록으로 카드를 그리고, 카드마다 세 문서 링크를 붙인다.

### 문장은 본인이 쓴다

버전 파일의 빈 자리에는 완성 문장 대신 `{ guide: [...] }` 로 **작성 안내**를 둔다.
AI 가 쓴 문장은 채용 과정에서 걸러진다는 판단에 따라, 도구는 무엇을 쓸지만 제시하고
문장 자체는 본인이 쓴다. 안내는 화면에 점선 상자로 그려져 완성 문장과 구분되며,
남은 개수는 `tools/check.js` 가 세어 준다.

자기소개서는 지원처마다 글이 통째로 달라 공유할 문장이 거의 없다. `data.js` 에는 이름과
서명만 두고, 내용은 버전 파일이 각자 갖는다.

**본문이 스크립트로 그려진다.** 자바스크립트가 꺼진 환경에서는 안내 문구만 보인다.
언어 전환·페이지 분할·PDF 버튼이 이미 모두 스크립트에 기대고 있어, 버전 기능을 얻는
대가로 감수하기로 한 제약이다.

### 분할 단위

최상위 블록에 `data-doc-block` 을 붙인 요소가 분할 단위다. 경력에서는 **회사 머리글
(`.doc-entry`)과 성과 한 건(`.doc-point`)이 각각 별도 블록**이다. 회사 전체를 한 덩어리로
두면 긴 경력이 통째로 다음 장으로 밀려 페이지 아래가 크게 빈다.

절 제목과 회사 머리글(`data-doc-keep`)은 페이지 맨 아래에 홀로 남지 않는다. 화면 분할과
인쇄 분할이 같은 대상에 같은 규칙을 적용한다.

**화면과 인쇄의 글자 밀도는 반드시 같아야 한다.** `@media print` 에서 글자 크기나 여백을
바꾸면 두 분할이 갈린다. 실제로 인쇄에서만 본문을 13.5px 로 줄였다가 KO 기준 화면 4장 /
PDF 3페이지로 어긋난 적이 있어, 지금은 한 값만 쓴다.

## 8. 16:9 슬라이드 덱 (`/portfolio`)

### 캔버스

1280×720 (16:9). 화면에서는 `1rem` 을 뷰포트에서 역산해 캔버스 전체가 항상 화면에 들어오게
하고, 인쇄에서는 `1rem = 20px` 로 고정해 정확히 1280×720px 가 되게 한다. 슬라이드 내부는
`px` 가 아니라 `rem` 으로 배치해야 두 경로에서 같은 비율이 유지된다.

### 슬라이드 데이터

`versions/<이름>.js` 의 `slides` 배열 **순서가 곧 슬라이드 순서**다. 마크업 순서는 보지 않는다.
마크업은 모든 슬라이드를 담은 모음집이고, 버전이 고르지 않은 장은 DOM 에서 제거된다 —
화면에도 PDF 에도 나오지 않는다. 순서도 DOM 을 재배치해 맞추므로 PDF 순서가 화면과 같다.

문서와 마찬가지로 `?v=<이름>` 으로 버전을 고르고, 기본판이 아니면 `noindex` 가 붙는다.

| 옵션 | 뜻 |
| --- | --- |
| `id` | 마크업의 `data-slide` 와 짝을 이루는 식별자 |
| `enabled: false` | 아직 공개하지 않을 장. DOM 에서 제거되어 PDF 에도 빠진다. `?preview=all` 로 확인 |
| `appendix: true` | 부록. 본편과 번호를 따로 세고, 진행 바는 본편 기준으로 계산한다 |

### 조작

| 입력 | 동작 |
| --- | --- |
| `→` `PageDown` `Space` / `←` `PageUp` | 다음 / 이전 |
| `Home` `End` | 처음 / 마지막 |
| `F` | 전체화면 (요소 전체화면이 막힌 환경에서는 컨트롤만 접는 대체 모드) |
| 좌우 스와이프 | 슬라이드 넘김 (세로 이동이 더 크면 무시해 스크롤과 충돌하지 않는다) |
| `#/3` | 3번 슬라이드로 직접 진입 |
| `?lang=en` | 언어 지정 진입 |

전체화면에서 2.6초간 입력이 없으면 컨트롤과 커서를 감춘다(발표용).

## 9. PDF 추출

### 요구사항

- 화면에 보이지 않던 부분도 모두 포함
- 배경색·그라디언트가 그대로 출력
- 현재 선택된 언어로 출력 (KO/EN 두 벌이 필요하면 언어를 바꿔 두 번 저장)

### 방법

상단 바의 PDF 버튼(또는 `Ctrl`/`Cmd`+`P`)을 누르면 브라우저 인쇄 대화상자가 열린다.
버튼 경로에서는 인쇄 직전에 **화면 밖 이미지를 강제로 내려받고 완료를 기다린 뒤** 대화상자를
연다. 지연 로딩된 이미지가 빈 칸으로 찍히는 것을 막기 위한 처리다.

저장 설정

| 항목 | A4 세로 문서 | 16:9 덱 |
| --- | --- | --- |
| 대상 | PDF로 저장 | PDF로 저장 |
| 용지 | A4 (기본값 유지) | 기본값 유지 (`@page` 가 1280×720px 지정) |
| 여백 | **기본값** — `@page` 가 18/16mm 를 이미 잡는다 | **없음** |
| 배경 그래픽 | 켜기 | 켜기 |

문서에서 여백을 '없음'으로 고르면 글이 종이 끝에 붙으므로 주의한다.

### 검증 결과 (2026-08-24, Chrome 헤드리스)

| 페이지 | 용지 | 페이지 수 | 화면 장수 |
| --- | --- | --- | --- |
| `/cv` | 594.96×841.92pt = A4 세로 | KO 3 / EN 4 | 일치 |
| `/coverletter` | 동일 | 2 (내용 길이에 따라 변동) | 일치 |
| `/portfolio` | 960×540pt = 1280×720px @96DPI | 8 (본편 7 + 부록 1) | — |

`tools/print-pages.ps1` 로 재현한다. 문서는 장수를 고정값으로 검사하지 않고 용지 크기만
확인하며, 덱은 슬라이드 수와 페이지 수가 일치해야 한다.

## 10. 다국어

- 지원 언어: **한국어(ko), 영어(en)**. 기본값은 브라우저 언어가 한국어면 `ko`, 아니면 `en`.
- 우선순위: `?lang=` 쿼리 → `localStorage.language` → 브라우저 언어.
- 저장 키 `language` 를 **메인 페이지·문서·덱이 모두 공유**한다. 한 곳에서 고른 언어가
  사이트 전체에서 이어진다.
- 마크업에는 텍스트를 직접 쓰지 않고 키로 연결한다.

| 위치 | 속성 | 사전 |
| --- | --- | --- |
| 메인 | `data-key`, `data-key-aria-label`, `data-key-title` | `js/i18n.js` |
| 문서 | `data-doc-key`, `data-doc-key-aria-label`, `data-doc-key-title` | `<문서>/text.js` |
| 문서 셸 UI | 위와 같음 | `paper/shared/paper.js` 의 `UI_I18N` |
| 덱 | `data-deck-key`, `data-deck-key-alt`, `data-deck-key-aria-label` | `portfolio/slides.js` |
| 덱 셸 UI | 위와 같음 | `slides/shared/deck.js` 의 `UI_I18N` |

`en` 값이 없으면 `ko` 로 대체된다. 키 누락과 미사용 키는 `tools/check.js` 가 잡는다.

문서의 절 번호(`.doc-heading-no`)는 번역 대상이 아니다. 언어와 무관한 값이라 KO/EN 어느
쪽에서도 같은 내용이 두 번 나오지 않는다.

일본어가 필요해지면 각 사전에 `ja` 블록을 추가하고 `LANGS` 배열과 언어 버튼에 항목을 더하면
된다. 구조 변경 없이 확장 가능하도록 만들어 두었다.

## 12. 개발 하네스

### 로컬 미리보기

정적 서버로 연다. `cv/` 같은 디렉터리 링크는 `file://` 에서 `index.html` 로 이어지지 않으므로
서버로 여는 쪽이 안전하다.

```bash
npx serve .                  # 또는
python -m http.server 8000
```

`http://localhost:8000/` 에서 메인, `/cv/`, `/coverletter/`, `/portfolio/` 를 확인한다.
빌드·감시(watch) 과정이 없으므로 파일을 저장하고 새로고침하면 끝이다.

### 점검 스크립트

빌드 단계가 없다는 것은 컴파일러가 실수를 잡아 주지 않는다는 뜻이다. 그 자리를 두 스크립트가
메운다.

| 명령 | 하는 일 |
| --- | --- |
| `node tools/check.js` | ① 로컬 자원 참조 ② `data-slide` ↔ `DECK_SLIDES` id ③ 덱 i18n 키 ④ 문서 셸 UI 키 ⑤ 문서 데이터 ko/en 짝 ⑥ 버전 정의 참조 유효성(경력·성과 id, `key`, 파일명↔`id`) ⑦ 메인 i18n 키 ⑧ 컨트롤러가 요구하는 DOM id |
| `powershell -ExecutionPolicy Bypass -File tools\print-pages.ps1` | Chrome 헤드리스로 세 페이지를 PDF 로 뽑아 용지 크기와 (덱은) 페이지 수를 대조 |

문구나 절을 고친 뒤에는 `check.js` 를, 인쇄 관련 CSS 를 손댄 뒤에는 `print-pages.ps1` 을
돌린다.

### AI 작업 규칙

`CLAUDE.md` 에 이 저장소의 작업 규칙을 둔다. 핵심은 다음과 같다.

- **`nnn-games-website/` 는 참고 전용이다.** 어떤 경우에도 수정하지 않는다. 별도 git
  저장소이며 이 사이트에 배포되지 않는다.
- 문구를 추가할 때 `ko`/`en` 두 사전을 함께 채운다.
- 지면 체계를 섞지 않는다. 문서는 `px`, 덱은 `rem`.
- 공용 폴더(`paper/shared/`, `slides/shared/`) 변경은 그 체계를 쓰는 모든 페이지에 적용된다.
- 변경 후 `node tools/check.js` 를 돌린다.

### 브라우저 지원

최신 Chrome / Edge / Safari / Firefox. `clamp()`, `color-mix()`, `inert`, `display: contents`,
`Promise`, `URLSearchParams` 를 쓴다. Internet Explorer 는 지원하지 않는다.
PDF 추출 결과는 Chromium 계열에서 가장 정확하다.
