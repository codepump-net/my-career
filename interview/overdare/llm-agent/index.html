01 · JOB REQUIREMENT

공고에서 무엇을 검증하는가

LLM Agent 자체는 우대요건입니다. 그러나 이를 제품으로 설명하려면 공고의 필수요건인 시스템 구조화·툴/API 설계·문서화·UX 분석을 먼저 충족해야 합니다.

“Agent를 써 봤다”가 아니라 “왜 이 구조를 선택했고 어떻게 안전성과 효과를 검증했는가”가 실무 면접의 질문입니다.

정확한 해석: 공고에는 LLM 경험을 필수라고 쓰지 않았습니다. 필수 역량은 제작 환경을 제품으로 정의하는 능력이고, LLM Agent 경험은 그 역량을 증폭하는 직접 우대 신호입니다.

필수 기반 · MUST

Agent보다 먼저 증명할 역량

AI가 없어도 성립해야 하는 TPM의 제품·기술 기본기입니다.

  • 복잡한 시스템을 단순화해 설명하고 구조화
  • 게임 시스템·툴·API를 논리적으로 정의하고 문서화
  • 아이디어를 PRD·기능 명세·플로우 차트로 구체화
  • 툴 사용자 관점에서 UX 흐름과 개선점을 도출
  • AI와 사람이 함께 만드는 방식을 제작 환경의 문제로 탐구
직접 우대 · PLUS

LLM Agent 관련 명시 항목

실제 프로젝트 적용과 결과를 확인하는 우대요건입니다.

  • LLM 기반 AI Agent 적용 — Agent·Skills·Tool Orchestration
  • Agent 프레임워크 사용 — LangChain·Claude Code·OpenCode 등
  • AI 콘텐츠 생성·자동화·개발 생산성 개선 프로젝트
  • 프레임워크 이름보다 적용 범위·실패·검증·사람의 책임을 증명
면접 핵심 명제: “Agent가 코드를 생성했습니다”에서 끝내지 않고, 입력을 계획으로 바꾸고 적절한 도구를 선택하며 결과를 검증하고 위험한 변경은 사람에게 승인을 요청하는 전체 루프를 설계했다고 설명해야 합니다.

02 · MENTAL MODEL

LLM, Agent, Workflow를 구분한다

세 용어를 구분하지 못하면 Agent 경험이 단순 프롬프트 사용으로 축소됩니다. 먼저 실행 주체와 제어권이 어디에 있는지 나눕니다.

01 · MODEL

LLM 호출

입력 컨텍스트를 받아 다음 출력 토큰을 생성합니다. 한 번의 생성만으로 외부 상태가 바뀌지는 않습니다.

02 · AGENT

Agent 실행 루프

모델이 목표와 현재 상태를 보고 다음 행동 또는 도구를 선택하고, 결과를 관찰해 종료 조건까지 반복합니다.

03 · WORKFLOW

Agentic Workflow

Agent 루프와 결정적 코드, 도구, 승인, 재시도, 관측·평가를 묶은 제품 수준의 전체 실행 시스템입니다.

01Goal · Context사용자 목표, 제약, 프로젝트 상태를 읽습니다.
02Input Guardrail범위·권한·위험한 입력을 먼저 검사합니다.
03Plan · Route작업을 나누고 다음 도구 또는 전문 역할을 고릅니다.
04Tool · Skill계약된 입력으로 외부 기능을 실행하고 결과를 돌려받습니다.
05Validate · Approve자동 검사 후 부작용이 있으면 사람의 승인을 받습니다.
06Trace · Evaluate결과와 전체 경로를 기록하고 기준에 따라 평가합니다.
반복 루프: 도구 결과가 부족하면 03으로 돌아가되 최대 턴·시간·비용·재시도 한도를 둡니다.
종료 루프: 수용 기준 통과, 사용자 승인, 명시적 실패 또는 예산 소진 중 하나로 끝납니다.

03 · CLAUDE CODE MAPPING

공통 원리를 Claude Code 구현과 연결한다

Claude Code는 Agent 루프를 새로 설계하는 프레임워크라기보다, 파일·검색·실행 도구를 가진 코딩 Agent에 컨텍스트·절차·격리·자동화·권한 계층을 붙이는 실행 환경입니다.

공고가 Claude Code 사용 경험을 따로 적은 이유는 “채팅 사용”보다 이 확장 계층을 실제 프로젝트에 적용했는지 보기 위해서라고 해석할 수 있습니다.

공통점: OpenAI와 Anthropic 문서 모두 Agent를 모델 단독이 아니라 지침, Tool, 컨텍스트·상태, 위임, 안전 통제, 평가가 결합된 워크플로로 설명합니다. 차이는 원리보다 제품에서 그 책임을 노출하는 이름과 실행 표면에 있습니다.

CLAUDE.md ≠ Enforcement

지침은 모델이 따르는 컨텍스트입니다. 반드시 지켜야 하는 규칙은 PreToolUse Hook, Deny 규칙, Sandbox로 강제합니다.

Skill ≠ Hook · MCP

Skill은 추론이 필요한 지식·절차, Hook은 이벤트 기반 자동 실행, MCP는 새로운 외부 capability 연결입니다.

Subagent ≠ Handoff

Claude Code Subagent는 격리된 작업 결과를 메인 세션에 반환합니다. 최종 사용자 응답 소유권은 대체로 메인 Agent에 남습니다.

06 · DESIGN PRACTICE

OVERDARE형 Agent를 설계해 본다

면접 현장 과제로 나올 수 있는 “AI로 Obby 게임을 만들어 줘” 요청을 제품 수준의 워크플로로 바꾸는 연습입니다.

실습 · Obby 제작 Agent

사용자 요청: “친구 8명이 모바일에서 10분 동안 즐길 수 있는 물 테마 Obby를 만들어 줘.”
  1. 요구 최소 확인대상 숙련도·플레이 시간·협동/경쟁·아트 방향만 묻고, 나머지는 가정으로 명시합니다.
  2. 계획과 변경 범위 제시코어 루프, 체크포인트 수, 생성할 객체·스크립트·에셋, 비목표를 사용자에게 보여줍니다.
  3. 검증된 템플릿에서 생성프로젝트 스키마·API 문서·에셋 카탈로그를 조회하고 작은 플레이 가능한 세로 조각부터 만듭니다.
  4. 자동 검증API 유효성, 서버/클라이언트 권한, 도달 가능성, 8인 동시성, 모바일 성능, 에셋 권리를 검사합니다.
  5. Diff와 사람 승인코드뿐 아니라 객체·설정·에셋 변경을 미리 보여주고 적용할 항목을 선택하게 합니다.
  6. 샌드박스 플레이 테스트봇과 실제 세션에서 이탈·재접속·중복 보상·타임아웃을 시험하고 실패하면 체크포인트로 되돌립니다.
  7. 배포 전 별도 승인외부 공개·결제·데이터 변경은 다시 승인받고, 버전·생성 이력·롤백 지점을 남깁니다.

ARTIFACT 01

입력·컨텍스트·역할·도구·검증·사람 승인·종료 조건을 한 장에 표시합니다.

ARTIFACT 03

ARTIFACT 04

생산성 비교표

도입 전후 리드타임·재작업·결함·사람 개입 시간과 제품 결과를 함께 비교합니다.

1 · 문제누가 어디서 막혔는가
2 · 구조왜 Agent가 필요한가
3 · 경계AI·도구·사람의 책임
4 · 검증실패·안전·평가 방법

“AI가 전부 만들었습니다”사람의 제품 판단과 품질 책임이 사라집니다.
“Agent를 여러 개 두었습니다”분리 이유·소유권·비용이 없으면 복잡성만 늘린 설계입니다.
