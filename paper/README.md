# A4 세로 문서

`paper/shared/` 는 워드 문서처럼 읽고 A4 로 출력하는 문서 체계다. 회색 배경 위의 흰 종이
화면, 언어 전환, **A4 세로 인쇄 레이아웃**, 화면용 페이지 분할, 그리고 **버전 관리**를 이
폴더가 책임진다.

이 체계를 쓰는 페이지는 `/cv` 와 `/coverletter` 다.
발표용 16:9 덱(`/portfolio`)은 별개 체계다 — [`slides/README.md`](../slides/README.md) 참고.

```text
cv/
  index.html         # 버전 목록 페이지 (링크만)
  data.js            # 경력 정본 — 사실은 여기에만 적는다
  default/           # 버전 하나 = 폴더 하나
    index.html       #   문서 셸
    version.js       #   이 버전의 절 구성·순서
  research/          # 연구·교육 지원용 본보기
  overdare/          # OVERDARE TPM 지원용
coverletter/
  index.html         # 버전 목록 페이지
  data.js            # 공통 껍데기(이름, 서명) — 공유할 문장이 거의 없다
  default/
  overdare/
paper/shared/
  paper.css          # 시트 화면 + 문서 요소 + 인쇄 규칙
  paper.js           # 버전 로드 + 언어 전환 + 화면 페이지 분할 + PDF 추출
  render.js          # 데이터 → DOM
```

## 버전

지원 분야마다 이력서를 다시 쓰되 **경력 사실은 한 벌만 둔다.** `data.js` 에 사실을 적고,
버전 파일은 "어떤 절을, 어떤 순서로, 어떤 항목만" 보일지를 정한다. 회사명이나 성과 한 줄을
고치면 모든 버전에 함께 반영된다.

| | 주소 | 검색 노출 |
| --- | --- | --- |
| 버전 목록 | `/cv/` | 허용 |
| 기본판 | `/cv/default/` | 허용 |
| 맞춤 버전 | `/cv/overdare/` | `noindex` 자동 부착 |

`/cv/` 는 버전 목록만 보여 주고, 실제 문서는 각 버전 폴더에 있다.

**모든 버전은 메인 페이지의 지원 목록(`applications.js`)에 공개된다.** 지원처끼리 서로의
문서를 볼 수 있다는 뜻이다. `noindex` 는 검색 결과에 뜨는 것만 막는다.
특정 지원을 감추려면 `applications.js` 에서 항목을 빼고 링크만 직접 전달한다
(주소를 아는 사람은 여전히 열 수 있다).

### 새 버전 만들기

1. `default/` 폴더를 통째로 복사해 `<이름>/` 으로 둔다.
2. `version.js` 의 `id` 를 폴더명과 같게 바꾼다. (어긋나면 `tools/check.js` 가 잡는다)
3. `sections` 를 원하는 순서로 배열한다.
4. 루트 `applications.js` 에 이 버전을 쓰는 지원 항목을 넣는다.
   목록에 없으면 어디서도 링크되지 않는다 — `check.js` 가 고아 폴더로 잡아 준다.
5. `/<문서>/<이름>/` 으로 열린다.

### 문장은 본인이 쓴다

버전 파일의 빈 자리에는 완성 문장 대신 **작성 안내**를 둔다. 화면에는 점선 상자로 그려져
완성 문장과 구분되고, 그대로 제출하면 곧바로 눈에 띈다.

```js
// 아직 안 쓴 자리
{ guide: ['무엇을 쓰면 좋은지', '무엇을 피해야 하는지'] }

// 다 쓴 자리
{ text: { ko: '…', en: '…' } }
```

`guide` 는 작성자용 메모라 번역하지 않는다(한국어 한 줄 또는 줄 목록).
남아 있는 안내 블록 수는 `node tools/check.js` 가 세어 준다.

절 전체가 아직 안 쓴 상태면 `{ type: 'text', title: {…}, guide: [...] }` 로 둔다.
한 줄 소개(`head.tagline`)도 `{ guide: [...] }` 를 받는다.

지원 건마다 무엇을 앞세우고 무엇을 피할지는 `docs/applications/<지원>.md` 에 정리한다.
버전 파일의 안내는 그 메모의 결론을 자리별로 옮긴 것이다.

### 절 정의

```js
{ type: 'text',       key: 'summary',  title: {ko,en} }   // 정본 문단
{ type: 'text',       content: {ko,en}, title: {ko,en} }  // 버전 전용 문단(정본을 덮어씀)
{ type: 'prose',      paragraphs: [ {ko,en}, … ], title: {ko,en} }
{ type: 'experience', title: {ko,en} }                    // 경력 전체
{ type: 'experience', title: {ko,en}, include: [ … ] }    // 고른 경력만, 적은 순서대로
{ type: 'list',       key: 'education', title: {ko,en} }
{ type: 'cite',       key: 'publication', title: {ko,en} }
{ type: 'closing',    paragraphs: [ … ], sign: {ko,en} }  // 제목 없이 맺음말만
```

`include` 항목은 id 문자열이거나 다음 형태다.

| 형태 | 뜻 |
| --- | --- |
| `{ id: '1m' }` | 그 경력 전체 |
| `{ id: '1m', points: ['ifland'] }` | 고른 성과만, 적은 순서대로 |
| `{ id: '1m', pointLimit: 2 }` | 앞에서 2건만 |
| `{ id: '1m', subs: false }` | 세부 항목 감춤 (분량을 줄일 때) |

절 번호(01, 02 …)는 제목이 있는 절에 자동으로 매겨진다. 직접 적지 않는다.

## 다국어

다국어 값은 `{ ko: '…', en: '…' }` 로 적는다. 문자열 하나만 적으면 번역하지 않는 값
(연도, 직함, 서비스명 등)으로 본다. `en` 이 비면 `ko` 로 대체되며, 짝이 맞지 않으면
`tools/check.js` 가 잡는다.

언어를 바꾸면 문자열을 갈아 끼우는 게 아니라 **다시 그린 뒤 다시 나눈다.** 번역문 길이가
달라 줄 수가 바뀌므로 페이지 분할도 함께 달라진다.

## 페이지 분할이 두 벌인 이유

| | 누가 나누나 | 목적 |
| --- | --- | --- |
| 화면 | `paper.js` 가 블록 높이를 재서 시트로 나눈다 | 워드처럼 보이게 하는 미리보기 |
| 인쇄 | 브라우저가 `@page` 여백에 맞춰 직접 나눈다 | **실제 결과. 이쪽이 기준이다** |

둘은 같은 여백·같은 글자 크기·같은 분할 회피 규칙을 쓰므로 장수가 일치한다.
화면 폭이 900px 미만이면 종이 흉내를 포기하고 한 줄기로 흘린다(모바일).

분할 단위는 렌더러가 `data-doc-block` 을 붙인 요소다. 경력에서는 **회사 머리글과 성과
한 건이 각각 별도 블록**이다. 회사 전체를 한 덩어리로 두면 긴 경력이 통째로 다음 장으로
밀려 페이지 아래가 크게 빈다. 회사 머리글에는 `data-doc-keep` 이 붙어 성과와 떨어지지
않는다.

## PDF 추출

상단 바의 PDF 버튼(또는 `Ctrl`/`Cmd` + `P`)을 누른다.

- 대상: **PDF로 저장**
- 용지: **A4** (`paper.css` 의 `@page` 가 지정하므로 기본값 그대로 둔다)
- 여백: **기본값** — 여백은 `@page { margin: 18mm 16mm }` 가 이미 잡고 있다.
  여기서 '없음'을 고르면 글이 종이 끝에 붙는다
- 배경 그래픽: **켜기**

페이지 수는 내용 길이에 따라 결정된다. 현재 보고 있는 **버전과 언어**로 출력되므로,
KO/EN 두 벌이 필요하면 언어를 바꿔 두 번 저장한다.

## 주의

- 문서 치수는 `rem` 이 아니라 **`px`** 를 쓴다. 슬라이드 덱과 반대다.
  덱은 화면 크기에 따라 배율이 변하지만, 문서는 실제 종이에 찍히는 크기가 고정이어야 한다.
  96dpi 기준 1px = 1/96 인치라 화면과 인쇄가 같은 크기로 맞는다.
- **`@media print` 에서 글자 크기나 여백을 바꾸지 않는다.** 화면과 인쇄가 다른 밀도로
  흐르면 화면 장수와 PDF 장수가 어긋난다. 실제로 인쇄에서만 본문을 13.5px 로 줄였다가
  KO 기준 화면 4장 / PDF 3페이지로 갈렸던 적이 있다.
- `paper.js` 의 `PAGE_CONTENT_H` 는 `paper.css` 의 `@page` 여백과 짝을 이룬다.
  여백을 바꾸면 두 곳을 함께 고친다.
- **버전 파일에 사실을 복사해 두지 않는다.** 정본이 둘이 되는 순간 갱신 누락이 생긴다.
  버전 전용 문단(요약 등)만 `content` 로 덮어쓴다.
- 본문이 스크립트로 그려지므로 자바스크립트가 꺼진 환경에서는 안내 문구만 보인다
  (`<noscript>`). 언어 전환·페이지 분할·PDF 버튼도 모두 스크립트에 기대고 있어,
  이 체계에서는 감수하기로 한 제약이다.
