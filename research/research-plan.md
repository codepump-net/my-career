# Roblox 기반 컴퓨터 그래픽스 및 융합 연구 계획서

**연구 방향: Computer Graphics · AI 활용 · MIS**  
**작성일·자료 확인일: 2026-09-19 | 계획 기간: 착수 후 36개월 | 상태: 실행 계획 초안**

**방향 갱신:** 연구 조사는 세 분야의 최고 수준 학술지·학회와 최신 동향을 각각 검토하는 방식으로 확장한다. ## 1. 연구 목적

아주대학교 교수 지원을 준비하는 과정에서 우선 보완할 부분을 최근의 학술 연구 실적으로 설정한다. 컴퓨터 그래픽스 연구와 게임·메타버스 개발 경험을 바탕으로 Roblox 및 관련 분야의 최신 연구를 지속적으로 분석하고, 재현 실험에서 발견한 문제를 독립적인 연구 질문으로 발전시킨다. 이를 통해 박사 졸업 연구를 완성하고, 이후에도 이어갈 수 있는 연구 주제와 논문 실적을 축적한다.

세 분야의 중심 질문은 다음과 같다.

| 분야 | 중심 질문 |
| --- | --- |
| Computer Graphics | 생성된 3D 콘텐츠가 의도한 동작을 유지하며 제한된 자원에서 실행되려면 어떤 표현·검증·최적화가 필요한가? |
| AI 활용 | AI가 Roblox 제작·코딩·테스트·상호작용 과제를 신뢰성 있게 수행하도록 어떻게 설계하고 평가할 것인가? |
| MIS | AI 도구와 플랫폼 정책은 창작자·조직의 행동, 생산성, 가치 창출에 어떤 영향을 미치는가? |

Roblox는 실제 제작·실행 환경이자 플랫폼 생태계의 연구 현장으로 활용한다. 기술 방법은 다른 환경으로의 일반화를, MIS 연구는 행동·조직 메커니즘과 적용 범위를 검증한다.

최신 논문의 요약과 구현 재현은 연구의 출발점이다. 학술 기여는 기존 방법과 구별되는 문제 정의, 알고리즘 또는 평가 체계, 통제된 비교 실험, 재현 가능한 산출물로 입증한다.

## 2. 현재 기반과 보완 방향

현재 이력의 근거는 [CV 정본](../cv/data.js)이다. 정본에는 컴퓨터 그래픽스 석사, 정보통신공학 박사 수료, SCA 2006의 인터랙티브 캐릭터 관련 논문과 실시간 애니메이션 등 강의 이력이 기록되어 있다. 이 계획은 해당 기반을 최근 생성형 3D·실시간 상호작용 연구와 연결한다. 학위 상태는 **박사 수료**로 유지하며, 아래 목표를 이미 달성한 성과로 기재하지 않는다.

| 보완할 부분 | 실행 방향 | 확보할 증빙 |
| --- | --- | --- |
| 최근 연구의 연속성 | 핵심 질문 아래 문헌 검토·재현·새 방법 개발을 이어간다 | 월간 연구 기록, 코드 이력, 실험 보고서 |
| 박사학위 완성 | 지도 체계와 학위 요건을 확인하고 핵심 과제 A·B를 학위논문으로 통합한다 | 연구계획 심사 자료, 논문 원고, 학위 심사 자료 |
| 독립적인 학술 기여 | 연구 질문 설정, 방법 설계, 실험·집필의 본인 기여를 기록한다 | 기여도 설명, 비교·구성요소 제거 실험, 원고 |
| 교수 지원용 대표 실적 | 검증된 결과를 논문·공개 코드·데모로 묶는다 | 게재·채택 증빙, DOI, 재현 안내, 발표 자료 |
| 교육·산학 연계 | 핵심 연구를 실습과 공동연구 제안으로 확장한다 | 제안 강의계획, 실습 과제, 공동연구 계획 |

박사 수료 이후의 학위 취득 가능 절차, 지도교수, 연구등록·논문 제출 기한, 학과별 논문 요건은 착수 첫 달에 소속 대학원과 확인한다. 아주대학교 교수 채용의 직급·트랙·실적 인정 기간·저자 및 학술지 인정 기준은 실제 지원 공고가 정해질 때 별도로 대조한다. 이 문서의 일정과 논문 목표는 대학의 공식 졸업·임용 기준이 아니다.

## 3. 최신 연구에서 도출한 방향

다음은 확인일 기준으로 검토한 출발 문헌이다. 공개 논문·기술 보고서·제품 문서를 구분했으며, 최신 연구 전체를 망라한 목록은 아니다. ‘후속 질문’은 문헌에서 착안한 제안으로, 연구 공백과 신규성이 입증된 상태는 아니다.

| 출발 자료 | 확인한 내용과 자료 성격 | 후속 질문 |
| --- | --- | --- |
| [Cube: A Roblox View of 3D Intelligence](https://arxiv.org/abs/2503.15475), 2025 | 3D 지능과 생성 모델을 다루는 arXiv 기술 보고서 | 생성 품질을 실제 사용 가능한 기능·실행 비용과 함께 평가할 수 있는가? |
| [CubePart](https://arxiv.org/abs/2605.28763), 2026 | 사용자 지정 부품 구조를 조건으로 하는 3D 생성 연구. [Roblox 공식 서지](https://about.roblox.com/publications/cubepart-open-vocabulary-part-controllable-3d-generator)는 SIGGRAPH 2026으로 표기한다 | 부품이 구성된 이후 관절·충돌·작동 범위를 검증하고, 단순화 이후에도 기능을 보존할 수 있는가? |
| [Controlling Quadric Error Simplification with Line Quadrics](https://onlinelibrary.wiley.com/doi/abs/10.1111/cgf.70184), 2025 | 메시 단순화에서 기하학적 특성을 제어하는 연구. [공식 서지](https://about.roblox.com/publications/controlling-quadric-error-simplification-line-quadrics)는 SGP 2025로 표기한다 | 부품 경계와 동작에 필요한 영역을 고려한 단순화는 정적 기하 오차만 사용하는 방법보다 유리한가? |
| [SmoothCache](https://about.roblox.com/publications/smoothcache-universal-inference-acceleration-technique-diffusion-transformers), 2025 | Diffusion Transformer의 추론 가속 연구. CVPR eLVM Workshop 발표로, 본회의 논문과 구분한다 | 제작 과정의 지연을 줄이는 기법을 적용할 때 품질·수정 횟수·작업 완료 시간은 어떻게 달라지는가? |
| [Roblox Model generation](https://create.roblox.com/docs/parts/model-generation) | 모델 생성 기능과 사용 흐름에 대한 제품 문서 | 실제 제작·실행 파이프라인에서 재현 가능한 평가 시나리오를 어떻게 구성할 것인가? |

Cube의 공개 구현에는 2025년 7월 v0.5와 2026년 5월 CubePart 업데이트가 안내되어 있다. 재현 단계에서는 사용할 코드 커밋·가중치·설정과 각 구성요소의 이용 조건을 고정한다. 제품 기능의 공개 상태와 연구용 모델의 사용 가능 범위는 따로 확인한다. [공식 코드 저장소](https://github.com/Roblox/cube).

CubePart가 이미 부품 제어와 엔진 연동을 제시한다는 점을 전제로, 단순히 부품 생성이나 스크립트 연결을 구현하는 것만으로 신규성을 주장하지 않는다. 또한 SmoothCache는 DiT 대상이므로 Cube의 자기회귀 생성 단계에 그대로 적용할 수 있다고 가정하지 않는다. 관련 모델 구조가 맞는 경우에만 확장 실험 후보로 검토한다.

## 4. 연구 범위와 우선순위

상위 연구 방향은 **Computer Graphics·AI 활용·MIS의 세 축**이다. 먼저 분야별 주요 학술지·학회와 최근 연구를 조사하고, 신규성·데이터 접근·재현 가능성·지도 적합성을 비교한다. AI 활용과 MIS는 그래픽스 연구 이후에만 착수하는 종속 분야로 두지 않는다.

아래 **A. 기능 검증·보정 → B. 기능 보존 단순화**는 그래픽스 축의 기존 박사논문 후보안이다. 두 과제는 동일한 부품 표현과 벤치마크를 공유하며, C·D·E는 이 후보안에서 파생된 확장 과제다. 세 분야의 독립적인 연구 후보와 초기 조사 일정은 [분야별 조사](literature/README.md)를 따른다.

| 구분 | 주제 | 역할 | 착수 조건 |
| --- | --- | --- | --- |
| A · 핵심 | 생성형 부품 모델의 기능 검증과 최소 보정 | 박사논문의 문제 정의·표현·검증 기반 | 공개 모델 재현 및 기능 실패 사례 확보 |
| B · 핵심 | 기능 보존 메시 단순화와 실시간 실행 | 박사논문의 알고리즘·성능 기여 | A의 데이터·평가 체계 고정 |
| C · 확장 | 제약과 검증 결과를 보여주는 제작 인터페이스 | HCI 연구 및 창작 도구 | A·B 도구 안정화와 참가자 연구 준비 |
| D · 확장 | 그래픽스·게임 제작 교육에서의 활용 | 교육 연구와 교수 지원 교육계획 | 수업 협력·연구 절차·평가 설계 확보 |
| E · 장기 후보 | 다중 사용자 환경의 동작 일관성과 비용 | 네트워크·시스템 후속 연구 | 단일 실행 환경에서 핵심 기여 검증 |

### A. 생성형 부품 모델의 기능 검증과 최소 보정

**연구 질문.** 사용자가 지정한 부품 구조와 동작 목표를 제약으로 표현하고 실행 결과를 피드백하면, 생성된 모델의 기능 실패를 줄이면서 외형 변경과 수작업을 제한할 수 있는가?

초기 대상은 경첩형 문·뚜껑, 회전 바퀴, 슬라이딩 서랍의 세 가지 강체 동작으로 제한한다. 사람형 캐릭터 전체의 리깅·보행·접촉 제어는 후속 범위로 둔다. 과거 인터랙티브 캐릭터 연구와는 ‘사용자 제어가 의도한 동작으로 이어지는 표현’이라는 문제의식으로 연결한다.

제안 방법은 다음 순서로 개발한다.

1. 부품, 연결 관계, 관절 종류·축·범위, 충돌 형상, 목표 동작을 기록하는 기능 그래프를 정의한다. 초기 입력은 사용자 지정 스키마와 수동 기준 주석을 허용한다.
2. 고정된 제어 입력으로 열기·회전·이동을 실행하고 관통, 분리, 목표 도달 실패를 자동 검사한다.
3. 관절 축·피벗·부품 간격·충돌 대리 형상 등을 조정하는 제한된 보정기를 만든다. 시각적 변형 비용과 기능 제약을 함께 최적화한다.
4. 미관찰 형상과 부품 조합에서 검증하고, 다른 시뮬레이터의 일부 사례에서도 결과를 확인한다.

| 항목 | 실험 설계 |
| --- | --- |
| 비교군 | 생성 결과+고정 관절 템플릿, 규칙 기반 보정, 제안 보정, 수동 보정 참조 |
| 주 지표 | 기능 성공률: 지정 범위 도달·연결 유지·허용치 이하 관통을 모두 충족한 사례 비율 |
| 보조 지표 | 관통 깊이·빈도, 목표 궤적 오차, 외형 변형량, 보정 시간, 수동 개입 횟수 |
| 구성요소 제거 | 기능 그래프 제약 제거, 충돌 항 제거, 실행 피드백 제거 |
| 기여 후보 | 생성 결과의 기능 실패 분류, 실행 기반 최소 보정 방법, 재현 가능한 기능 평가 세트 |

관통 허용치와 목표 오차는 물체 크기로 정규화하고 파일럿 이후 본실험 전에 고정한다. 수동 주석에 필요한 시간을 총비용에 포함한다. 보정으로 문제가 생기거나 해결되지 않은 사례도 그대로 집계한다.

**진행 판단.** 첫 3개월 안에 비교 가능한 실패 사례와 반복 실행 가능한 평가가 확보되어야 한다. 이후에도 규칙 기반 방법을 넘어서는 이득이 없으면 대형 모델 학습으로 확대하지 않고, 평가 체계의 기여 가능성을 검토하거나 B를 중심 과제로 전환한다.

### B. 기능 보존 메시 단순화와 실시간 실행

**연구 질문.** 같은 삼각형 수 또는 같은 실행 비용에서 관절 주변·접촉면·부품 경계를 보존하는 단순화가 일반 기하 기반 단순화보다 동작 성공률을 높일 수 있는가?

기하 오차에 기능 중요도와 동작 중 접촉·간섭 오차를 결합한 단순화 기준을 개발한다. 시각 메시와 충돌 메시를 구분하여 어느 변경이 어떤 효과를 냈는지 분리한다. 초기 연구는 외부에서 메시를 처리하여 Roblox로 가져오는 방식으로 수행하고, 엔진 내부 렌더러나 비공개 API 수정은 전제로 하지 않는다.

| 항목 | 실험 설계 |
| --- | --- |
| 비교군 | 원본, 일반 QEM, Line Quadrics 계열, 단순 부품 경계 보존, 제안 방법 |
| 통제 조건 | 같은 삼각형 예산·동작 입력·장면 밀도. 시각 메시만 변경한 조건과 충돌 메시지만 변경한 조건을 분리 |
| 주 지표 | 단순화 비율별 기능 성공률 및 기능 품질–실행 비용 곡선 |
| 보조 지표 | 표면·실루엣 오차, 관통, 전처리 시간, 메모리, 프레임 시간 중앙값·p95·p99 |
| 구성요소 제거 | 관절 중요도 제거, 접촉면 가중치 제거, 동작 기반 항 제거 |
| 일반화 | 미관찰 물체 범주, 다른 장면 밀도, 모바일·PC, 별도 엔진의 대표 사례 |

Roblox의 프레임별 애니메이션·물리·스크립트·렌더링 비용은 [MicroProfiler](https://create.roblox.com/docs/performance-optimization/microprofiler)를 활용해 조사한다. 낮은 삼각형 수가 반드시 전체 실행 시간 감소로 이어진다고 가정하지 않고 병목별로 해석한다.

**진행 판단.** 사전 고정한 시각 품질 허용 범위 안에서 기능 보존 또는 실행 비용의 유의미한 이득을 보여야 한다. 렌더링 이득이 없으면 결과를 숨기지 않고 충돌 계산·기능 보존으로 주장 범위를 좁힌다. 장면별 수작업 가중치에 과도하게 의존하면 일반화 개선을 우선한다.

### C. HCI: 의도와 검증 결과를 연결하는 제작 도구

부품·관절·목표 동작·실패 원인을 시각적으로 제시하는 인터페이스가 프롬프트 중심 제작보다 수정 비용을 줄이는지 연구한다. 프롬프트 중심, 제약 편집, 제약 편집+실행 피드백의 세 조건을 비교하고, 작업 완료 시간·최종 기능 성공률·수정 횟수·주관적 작업 부담을 측정한다.

파일럿에서 효과 크기와 분산을 추정한 뒤 참가자 수를 정한다. 숙련도와 과제 순서를 통제하고, 연구 참여 동의와 기관의 심의 필요 여부를 확인한 후 진행한다. 최초 연구는 성인 제작자를 대상으로 설계한다. 논문 후보 분야는 창작 지원·3D 상호작용이며, 핵심 알고리즘이 안정된 뒤 착수한다.

### D·E. 교육 및 시스템 확장

교육 연구에서는 제약·동작·성능을 직접 비교하는 실습이 그래픽스 개념 이해와 새로운 문제로의 전이에 미치는 영향을 평가한다. 사전·사후 평가와 일정 기간 후 전이 과제를 사용하고, 만족도를 학습 효과의 대리 지표로만 사용하지 않는다. 수업 운영과 연구 참여를 분리할 수 있는 협력 환경이 확보될 때 진행한다.

시스템 연구에서는 동일한 생성 자산이 다중 사용자 실행에서 유지해야 할 동작 상태와 전송 비용을 다룬다. 지정 지연·손실 조건에서 상태 불일치와 복구 시간 등을 측정하는 방향이며, 플랫폼 내부 데이터 없이 재현할 수 있는 범위부터 탐색한다. 두 확장 모두 현재의 확정된 논문 기여가 아닌 후속 후보이다.

## 5. 공통 실험·재현 계획

### 데이터와 비교의 공정성

- 최초 파일럿은 세 동작 범주의 총 30개 자산으로 시작한다. 본실험은 파일럿 분산·계산 비용에 따라 규모를 결정하며, 최소 100개 규모의 평가 세트 구축을 작업 목표로 둔다. 통계적 충분성이 확보된 수라는 의미는 아니다.
- 생성 자산과 직접 제작한 기준 자산을 함께 사용한다. 원본 출처·생성 프롬프트·시드·부품 주석·라이선스·실패 여부를 기록한다.
- 같은 원형의 변형은 학습·개발·평가에 나누어 넣지 않는다. 범주·원형 단위로 분리하고, 학습을 하지 않는 방법도 파라미터 조정용 세트와 최종 평가 세트를 구분한다.
- 생성 실패와 가져오기 실패를 포함한 전체 파이프라인 성공률, 정상 입력에 대한 알고리즘 성공률을 각각 보고한다. 공개 모델의 학습 데이터 전체를 알 수 없다면 중복 검증의 한계를 명시한다.
- 비교군은 원 논문·공개 구현을 우선하며, 재구현한 부분과 튜닝 예산을 밝힌다. 상용 기능은 접근 권한과 버전에 따라 재현이 달라지므로 공개 기준선도 유지한다.

### 측정과 분석

- 동일한 자산·입력에 대한 대응 비교를 기본으로 한다. 반복 프레임을 독립된 자산 표본처럼 세지 않고, 자산·실행·기기 수준을 구분하여 신뢰구간과 효과 크기를 보고한다.
- 생성·시뮬레이션의 확률적 변동은 복수 시드로 측정한다. 성능 측정은 워밍업·측정 시간·반복 수·기기 온도 조건을 고정하고, 본실험 전 주 지표와 제외 기준을 문서화한다.
- 기기 모델, OS, Roblox Studio·클라이언트 버전, 그래픽 설정, 해상도, 장면, 카메라, 네트워크 조건을 기록한다. 엔진 업데이트 전후 결과는 별도 실험군으로 관리한다.
- 플랫폼 영향을 분리하기 위해 기하·기능 지표를 외부 평가기에서 재측정하고, 대표 사례를 다른 엔진에서도 검증한다. 일부 사례만 확인했다면 그 범위를 명시한다.
- 성공률 개선 폭 같은 수치는 파일럿 이후 진행 판단 기준으로 정한다. 계획 단계에서 임의의 성능 향상을 예상 결과로 확정하지 않는다.

### 자원 계획

초기 투입량은 **주 15~20시간의 개인 연구**를 가정한다. 실제 가용 시간과 지도 여건이 다르면 일정부터 조정한다. 첫 달은 문헌·공개 코드·소규모 추론에 집중하고 기반 모델의 처음부터 학습은 범위에 넣지 않는다.

Cube 저장소가 안내하는 추론 메모리 기준은 일반 모드 16GB, 빠른 추론 24GB 이상의 GPU VRAM이다. 이는 해당 구현의 안내이며 CubePart 전체나 후속 학습의 자원 요구를 보장하지 않는다. 보유 장비에서 먼저 시험하고 필요한 경우 기관 자원 또는 단기 GPU 임대를 검토한다. [하드웨어 안내](https://github.com/Roblox/cube#hardware-requirements).

월별로 GPU 시간, 생성 건수, 실패 재시도, 저장량, 실험당 소요 시간을 기록한다. 유료 자원은 첫 파일럿의 실측량과 당시 견적으로 예산 상한을 정한 후 사용한다. 실행 검증은 우선 접근 가능한 PC·모바일 각 1대로 시작하고, 논문 단계에서 장비 범위를 넓힌다. 협력자·학생·연구비 확보는 현재 사실로 가정하지 않는다.

## 6. 박사학위 및 논문 실적 계획

학위논문 가제는 **「생성형 3D 콘텐츠의 기능 검증과 실시간 실행을 위한 구조 보존 방법」**으로 둔다. 핵심 주장은 ‘기능을 명시적으로 표현하고 검증하면 생성 후 보정과 경량화 과정에서 동작 품질을 체계적으로 관리할 수 있다’이며, 실험 결과에 따라 수정한다.

학위논문은 문제·관련 연구, 기능 표현과 평가 체계, A의 검증·보정, B의 기능 보존 단순화, 통합 실험·일반화·한계의 흐름으로 구성한다. 공개 모델이나 제품의 기능 설명과 본인이 개발한 기여를 장별로 구분한다.

| 산출물 | 내부 작업 목표 | 내용 및 판단 기준 |
| --- | --- | --- |
| 재현·벤치마크 보고서 | 1~6개월 | 출발 모델과 비교군 재현, 실패 유형, 평가 프로토콜. 독립 논문 투고는 기여가 충분할 때 판단 |
| 핵심 논문 A | 7~12개월 초고·첫 투고 목표 | 기능 검증·최소 보정의 독립 기여와 평가 |
| 핵심 논문 B | 13~24개월 초고·첫 투고 목표 | 기능 보존 단순화의 독립 기여와 실시간 검증 |
| 박사학위논문 | 25~30개월 통합·심사 준비 목표 | 학위 요건 충족 및 지도교수와 합의한 심사 일정에 연동 |
| 확장 논문 C 또는 D | 25~36개월 후보 | 핵심 연구 안정화 이후 HCI 또는 교육 중 하나 선택 |
| 교수 지원 연구 자료 | 분기 갱신, 31~36개월 통합 | 대표 논문, 기여도, 코드·데모, 후속 3년 계획 |

3년간 핵심 논문 2편과 확장 논문 1편의 투고를 지향하되, 채택·게재와 학위 취득 시점은 보장하지 않는다. 저자 순서는 실제 기여와 공동연구 합의에 따라 정하고, 본인 주도 기여를 명확히 남긴다. 동일 결과를 독립 성과처럼 중복 계산하지 않는다.

투고처 탐색은 과제 A의 애니메이션·상호작용, B의 기하처리·실시간 그래픽스, C의 창작 지원 분야를 기준으로 시작한다. 출발 문헌의 SCA·SGP·SIGGRAPH 등을 관련 연구 지형으로 참고하되, 투고 시점에 각 학회·저널의 공식 범위·논문 유형·일정과 대학의 인정 기준을 확인한 후 결정한다. 워크숍, 사전공개, 투고 중, 채택, 정식 게재를 서로 다른 상태로 기록한다.

매주 문헌 검토 1회와 실험 기록 갱신을 진행한다. 매월 결과 그림 또는 표 1개와 다음 달의 검증 질문을 남긴다. 분기마다 신규성, 기준선 대비 효과, 재현성, 투입 비용을 검토하여 **진행·범위 축소·주제 전환** 중 하나를 결정한다. 논문 수를 맞추기 위해 기여가 약한 결과를 불필요하게 나누지 않는다.

## 8. 아주대학교 교수 지원으로의 연결

연구 소개의 중심은 ‘게임·메타버스 현장의 제작과 실행 문제를 그래픽스 알고리즘과 실험으로 해결하는 연구자’로 설정한다. 디지털미디어학과를 염두에 둔 기존 지원 자료와 연결하되, 현행 학과 수요나 특정 공고와의 적합성이 검증되었다고 표현하지 않는다.

대표 연구마다 문제, 기존 방법의 한계, 본인의 방법, 정량 결과, 실패 사례, 활용 가능성을 설명하는 1쪽 요약과 짧은 데모를 준비한다. 산업 프로젝트 경험은 연구 문제의 배경으로 활용하고, 학술 실적은 논문·심사·재현 증빙으로 제시한다.

교육 연계 제안은 컴퓨터 그래픽스, 실시간 애니메이션, 생성형 3D 콘텐츠 제작 실습으로 구성한다. 학생이 생성 결과를 직접 검사하고 개선 전후를 측정하는 과제를 설계한다. 연구실 운영은 소규모 재현 과제에서 시작해 알고리즘·도구·응용 과제로 확장하는 방식으로 제안한다. 이는 향후 교육·연구실 계획이며 기존 강의나 학생 지도 실적이 아니다.

산학협력은 UGC 제작 도구, 모바일 콘텐츠 최적화, 기능 평가 자동화를 공동연구 후보로 정리한다. 특정 기업과의 협약·데이터 제공·연구비 확보는 협의 전까지 계획으로만 표기한다.

- [ ] 대학원에 현재 학적, 학위 제출 가능 절차·기한, 지도 체계와 논문 요건 확인
- [ ] 주간 연구 시간, 사용 가능한 장비와 월간 예산 상한 정리

논문 검토에는 `서지·URL / 읽은 버전·날짜 / 연구 질문 / 방법 / 데이터·비교군 / 한계 / 재현 상태 / 후속 질문 / 기존 연구와의 차이`를 남긴다. 실험에는 `실험 ID / 가설 / 코드·모델 버전 / 데이터 목록 / 설정·시드 / 기기 / 원자료 위치 / 결과 / 실패 / 해석 / 다음 실험`을 남긴다.
